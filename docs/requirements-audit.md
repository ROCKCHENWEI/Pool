# Pool 运行框架设计审计

## 已落地

- ROCKCHENWEI/Pool 主基线：已采用 Rust workspace + `shared-core` 作为运行核心，并加入 P0/P1/P2 对应模块。
- image-blaster 资产契约：已加入 `worlds/<slug>` envelope、indexed file parser、隐藏 request metadata parser、mock 3DGS output contract。
- 当前中文原型迁移：已迁移到 `apps/web-prototype/`，保留节点图、运行中心、API 接入、Hermes、Agent CLI、软件矩阵和三类输出 UI。
- P0 Timeline：已实现 `Project`、`Shot`、`Segment`、`OutputTarget`。
- P1 Pool_node：已实现 `Workflow`、`WorkflowNode`、`WorkflowConnection`、连接类型、节点状态、拓扑排序、循环检测。
- P2 V.I.S.C：已实现 `ProviderAdapter`、`ProviderRegistry`、`SoftwareAdapterRegistry`、默认 Provider/软件矩阵与 MCP resource stub。
- ComfyUI Provider：已实现真实 HTTP/WebSocket adapter 骨架，包含 health、submit、poll、stream progress、download、download/index、verify 和 smoke example。
- Kling Provider：已实现真实 HTTP adapter 骨架，包含 Bearer/JWT auth、text2video/image2video submit、`ProviderRequest.input_paths` 到本地图片 image2video 的映射、poll、download、verify、脱敏 request metadata 和 smoke example。
- OpenAI image Provider：已实现真实 HTTP adapter 骨架，包含 Bearer auth、`gpt-image-2` 默认模型、generation/edit endpoint 切换、本地 image/mask 输入校验、`ProviderRequest.input_paths` 到 edit `input_images` 的映射、multipart edit 上传、base64/URL 输出落地、metadata、verify 和 smoke example。
- 通用 HTTP Media Provider：已实现 Midjourney、Nano Banana Pro、Suno 的 gateway adapter 骨架与 media profile mapping，包含 `pool_media_profile`、`provider_payload`、submit、poll、download、状态映射、URL/base64 输出落地、metadata 摘要、Runtime HTTP 调度和 smoke example。
- 3DGS Gateway Provider：已实现通用 HTTP adapter 骨架与 provider profile mapping，包含 Marble/TripoSplat/SAM-3D/Spark/群核默认 path、`pool_gateway_profile`、`provider_payload`、submit、poll、download、状态映射、indexed file 命名、request metadata 和 smoke example。
- Provider 接入合同：已实现 `provider_contracts_resource`、Runtime HTTP `/api/provider-contracts?provider_id=...`、MCP `pool://provider-contracts/<provider-id>` 和 CLI `provider-contracts [provider-id]`，机器可读暴露 native adapter、通用 AI media gateway、3DGS gateway 的 runtime body、submit/poll path、状态字段、输出字段、环境变量和本地文件优先策略，供 Hermes/Agent/gateway 开发者接真实厂商 SDK 前对齐契约。
- Provider gateway mock server：已新增本地 `provider_gateway_mock_server` example，覆盖 `/v1/media/jobs`、`/v1/3dgs/.../jobs` 和 `/outputs/...`，可在无真实厂商账号时验证 AI media 与 3DGS adapter 的 submit/poll/download、本地文件落地和 assets 入库。
- Provider gateway template：已新增 `provider_gateway_template` 翻译模板，可把 Pool `pool_media_profile` / `pool_gateway_profile` 与 `provider_payload` 转成真实 SDK/HTTP worker 所需的上游 endpoint env、API key env、request body、Pool-compatible response contract 和本地文件优先策略。
- Provider gateway worker：已新增本地 `provider_gateway_worker` HTTP forwarder，并通过 `pool-cli provider-gateway-worker-contract`、`pool-cli provider-gateway-worker`、Runtime HTTP `/api/provider-gateway-worker`、MCP `pool://provider-gateway-worker` 和 MCP tool `pool_provider_gateway_worker` 暴露给 Hermes/Agent CLI；可复用 template 翻译 Pool media/3DGS gateway request，转发到真实厂商 worker、官方 SDK 包装服务或本地 mock upstream，并把上游 job/status/outputs 规范化回 Pool-compatible response；同一合同已暴露 `conformance_runbook`，把 mock baseline、真实 upstream worker、AI media smoke、3DGS smoke、production matrix 和 validate/import 串成真实 Provider 接入验收路径。
- 软件控制执行：已实现 `SoftwareAdapter`、`SoftwareControlAction`、`SoftwareActionResult`、`UnrealMcpAdapter`、`HermesMcpAdapter`、`MockUnrealAdapter` 和 `SoftwareActionRunner`；Unreal MCP 请求已补 `pool_unreal_action` 与 `mcp_payload`，并通过 `/api/unreal-mcp-bridge`、`pool://unreal-mcp-bridge`、`pool-cli unreal-mcp-bridge` 和 MCP tool `pool_unreal_mcp_bridge` 暴露插件/gateway 侧 bridge contract；`integrations/unreal/PoolMcpBridge` 已提供可安装的 Unreal Python 插件脚手架，`unreal.create_scene` 可读取 assets/actors/cameras/lights/world origin 并写出 `pool_unreal_scene_assembly` manifest；Hermes MCP 请求已补 `pool_hermes_action` 与 `mcp_payload`，覆盖导入资产、创建关卡、运行视口、渲染、导出构建和 Agent 编排的 Pool 侧 action schema，`pool-cli hermes-mcp-bridge-worker` 已提供本地 dry-run/forwarder worker。
- 通用软件 CLI 控制：已实现 `CommandSoftwareAdapter`，支持 Blender/Nuke/Resolve/TouchDesigner 等 adapter 通过 `ExecuteCli` payload 受控执行命令，并写入 `software_actions` 审计。
- 桌面识别 fallback：已实现 `DesktopRecognitionAdapter`，支持将 `DesktopRecognition` 优先级或桌面动作落地为 `output/control/desktop-recognition/*.json` 控制请求，并补 `pool_desktop_action` 与 `desktop_payload`；Runtime HTTP 已支持 controller 读取请求队列和回填执行结果，写入 `software_actions` 审计、task 状态和事件流；`run_desktop_recognition_controller --mode=applescript` 可在 macOS 上通过 System Events 执行明确的应用激活、坐标点击、快捷键和文本输入，也可通过 `--vision-trace` 消费外部视觉/OCR trace 并把 `visual_targets` 解析成点击坐标；`--mode=vision-http` 可调用外部视觉/OCR endpoint 写入 Pool-compatible trace 并回填 `external_visual_model:true`。
- 桌面视觉 trace 证据：已新增 `run_desktop_vision_trace_smoke`，可通过 Runtime HTTP 写入 TouchDesigner 桌面识别任务、本地 Pool-compatible trace JSON、`screen_trace_path` 和 `controller_result.vision_trace_path`，并让 PRD readiness 在 `production_hardening.evidence.desktop_vision_evidence` 中区分 controller callback、trace、本地 smoke 与真实外部视觉模型证据；`production-evidence-desktop-vision --production-vision --trace <path> --external-action-id <id>` 可把成功的外部视觉/OCR controller 结果整理成 `desktop_vision[]` production evidence bundle，也可用 `--trace-env`、`--external-action-id-env` 和 `--production-attestation-env` 显式绑定外部 controller 提供的环境变量；本地 smoke、dry-run、AppleScript 与失败结果不会冒充真实视觉/OCR/屏幕采集模型。
- 任务队列：已实现任务状态机、高成本任务人工审批放行、Provider run 审批/重试恢复和软件动作人工确认/失败重试后的同 task 恢复执行。
- Provider 运行器：已实现 `ProviderTaskRunner`，统一串联 adapter 成本估算、`provider_requests` 请求/响应账本、默认高成本审批、审批/重试后恢复同一 task 执行、provider health、submit、poll、download、assets 入库、外部 progress event 和事件写入；Provider retry 会追加新的 `provider_requests` attempt，保留旧失败响应，并在 request JSON 中记录 retry parent。
- 三类输出交付包：已实现 `OutputPackageRunner`，可生成视频时间线、游戏构建、交互艺术 cue graph 三个本地 indexed manifest，并同步写入 tasks、assets、workflow_events 和 report summaries；`GET /api/output-packages` 与 `pool://output-packages` 已能读取三类 deliverable catalog，标记 ready/missing/本地文件缺失并暴露预览合同与控制路由；`POST /api/output-packages/results` 已能把 Resolve/Unreal/TouchDesigner/MadMapper 等后段执行结果写回本地 manifest 的 `execution_result` / `execution_history`。
- 本地内容爆发闭环：已实现 `ContentBurstRunner`，可将默认运行蓝图、本地项目包、Agent/Hermes 决策、3DGS、Unreal 和三类输出交付包串成一键执行链路。
- 软件控制运行器：已实现 `SoftwareActionRunner`，统一串联 task、confirmation gate、adapter health、execute、`software_actions` 审计和 `workflow_events`；Runtime HTTP 审批确认后会读取最近的 `software_actions.command_json`，清除确认标记，并用同一 task 恢复执行原软件动作；失败、可重试或已取消 task 会通过 `/api/tasks/retry` 按同一账本重跑。
- Agent/Hermes 会话运行器：已实现 `AgentSessionRunner`，统一 staging Hermes command、Agent CLI command、token budget、transcript/control 文件、`agent_sessions` 与事件写入；Hermes 支持显式 `execute:true` 的 HTTP endpoint 调用，Agent CLI 支持显式 `execute:true` 的 allowlist 受控执行；带 `execute:true` 的会话若先进入 `waiting_approval`，transcript 会记录 `execution_request`，审批/重试可用同一 task 恢复执行。

- SQLite repository：已实现 migration runner、默认运行蓝图落库、任务展开、事件写入和统计。
- Runtime snapshot：已实现 SQLite 只读 snapshot，导出 projects、workflows、node_states、tasks、assets、events、provider_requests、software_actions、agent_sessions、api_keys 和运行统计；api_keys 只返回脱敏状态。
- Runtime 消耗统计：`RuntimeSnapshot.stats` 已汇总 task estimated tokens、waiting approval estimated tokens、Agent token used/budget、token_total 和 budget_remaining，Web runtime loader 会优先读取该消耗汇总。
- Credential storage：已实现 API Key 本地存储、AES-256-GCM 加密封装、可选 macOS Keychain backend 和本地轮换审计；设置 `POOL_CREDENTIAL_STORE=keychain` 后新写入 key 进入系统钥匙串，SQLite 只保存 `pool:v1:keychain` 引用；设置 `POOL_CREDENTIAL_PASSPHRASE` 后可用 AES-256-GCM 封装保存，旧数据保持 legacy plaintext 兼容；`GET /api/api-keys?rotation_days=...` 和 `pool-cli api-keys --rotation-days` 会返回 backend/source/owner/age/rotation_due 摘要但不暴露明文。
- Web snapshot/runtime loader：`apps/web-prototype` 已支持 `?snapshot=...` 读取 `RuntimeSnapshot` JSON，也支持 `?runtime=...`、默认端口组自动发现、`?runtime_registry=` 服务注册表读取、`?runtime_ports=`/`?runtime_endpoints=` 候选地址覆盖、`?project=` 项目过滤和 `/api/projects` 项目列表读取本地 Runtime HTTP API；连接 runtime 时会读取 `/api/discovery` 作为 Agent/Hermes endpoint manifest、MCP resource/tool/prompt 摘要和 `serve-mcp` 启动命令来源，读取 `/api/runtime-graph` 作为节点拓扑、任务类型、连接通道和 label 来源，读取 `/api/runtime-execution-plan` 作为按拓扑排序的执行步骤、审批门、合同和推荐动作来源，读取 `/api/runtime-budget` 作为预算与凭证摘要，读取 `/api/runtime-preflight` 作为运行前检查和 `pool_worker_self_checks` 本地 worker smoke 推荐来源，读取 `/api/runtime-handoff` 作为执行接管 runbook、本地 worker smoke lane、离线接管包 lane 和 5 人团队 lane 绑定，读取 `/api/provider-contracts` 作为 Provider native/gateway contract 摘要，读取 `/api/provider-gateway-worker` 作为 AI media/3DGS gateway worker 启动与 endpoint env 摘要，读取 `/api/desktop-recognition/contract` 作为桌面 controller contract 摘要，读取 `/api/workflow-context?workflow_id=...` 作为当前 workflow 账本摘要，读取 `/api/prompts` 作为 Hermes/Agent runbook registry，并用 snapshot 叠加最新 task 状态；`/api/node-context?node_id=...` 可让 Agent/控制台按节点读取关联 tasks、assets、provider_requests、software_actions、agent_sessions 与 control_context 建议控制入口；所有返回 snapshot 的写操作会重新读取 `/api/discovery`、`/api/runtime-graph`、`/api/runtime-execution-plan`、`/api/runtime-budget`、`/api/runtime-preflight`、`/api/runtime-handoff`、`/api/provider-contracts`、`/api/provider-gateway-worker`、`/api/desktop-recognition/contract` 和 `/api/workflow-context` 后再合并，同时映射 nodes、connections、tasks、assets、events、provider_requests、software_actions、api_keys。
